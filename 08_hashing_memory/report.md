# Chapter 08 Report — Hashing & Memory Mapping

## 1. 实验回顾

本章实验比较了两种“查找方式”：

1. 线性查找（Linear Scan）
2. 哈希查找（Hash Lookup）

它们完成的是同一个任务：

> 给定一个 token，找到对应的 embedding 向量。

不同的是：

- 线性查找需要遍历；
- 哈希查找可以直接定位。

这体现了两种完全不同的“记忆方式”。

---

## 2. 关键观察（重点是访问方式）

### 2.1 线性查找：通过搜索找到记忆

线性查找的过程是：

> 在所有候选中，一个一个对比。

特点：

- 不需要额外结构；
- 但查找成本随数据规模增长。

这类似于：

> “我记得这个东西，但我要慢慢想起来。”

---

### 2.2 哈希查找：直接命中记忆

哈希查找完全不同：

> 通过 key 直接定位存储位置。

特点：

- 查找时间接近 O(1)；
- 不依赖数据规模；
- 非常稳定。

这类似于：

> “我知道它在哪，一下就拿到。”

---

### 2.3 快速的代价：必须精确匹配

哈希的关键限制是：

> **必须完全匹配 key。**

例如：

```text
token_123 ✔
token_124 ✘（即使很相似）
这意味着：

哈希不支持“模糊匹配”；
无法处理“相似度问题”。
```
## 3. 概念映射
| 概念                | AI 中的真实含义  |
| ----------------- | ---------- |
| dict / hash table | 快速记忆结构     |
| key               | token / id |
| value             | embedding  |
| O(1) lookup       | 常数时间访问     |
| 精确匹配              | 非语义匹配      |

## 4. 本章核心认知收获

这一章让我真正理解：

AI 有两种完全不同的“记忆方式”：

基于地址的记忆（Hash）
基于相似度的记忆（Embedding Search）

前者：

快
精确
不理解内容

后者：

慢
模糊
有语义能力

## 5. 为什么这对 AI 极其重要

现实 AI 系统往往同时使用两种机制：
```
在 Transformer 中：
embedding lookup（哈希式）
attention（相似度计算）
在 RAG 系统中：
向量检索（相似度）
文档 ID 映射（哈希）

这说明：

AI = 记忆 + 搜索 的组合系统。
```
